用 interface 声明，生成 Go HTTP 客户端

写一个 Go interface，给每次调用加上注解，然后运行 go generate。生成的文件实现这个 interface，业务代码用普通的 Go 类型去调用。

声明式
Go
examples/github/api/api.go
package api

import (
	"context"

	"github.com/lexcao/genapi"
)

//go:generate go run ../../../cmd/genapi/main.go -file $GOFILE

// @BaseURL("https://api.github.com")
// @Header("Accept", "application/vnd.github.v3+json")
type GitHub interface {
	genapi.Interface

	// @GET("/repos/{owner}/{repo}/contributors")
	Contributors(ctx context.Context, owner string, repo string) ([]Contributor, error)

	// @POST("/repos/{owner}/{repo}/issues")
	CreateIssue(ctx context.Context, issue Issue, owner string, repo string) error
}

type Contributor struct {
	Login         string `json:"login"`
	Contributions int    `json:"contributions"`
}

type Issue struct {
	Title     string   `json:"title"`
	Body      string   `json:"body"`
	Assignees []string `json:"assignees"`
	Milestone int      `json:"milestone"`
	Labels    []string `json:"labels"`
}

为什么用 genapi

少写样板代码

你维护的是 interface。go generate 写下调用 HTTP 客户端的方法体。

类型检查

参数和返回值都是普通 Go 类型，在编译这个包时检查。

接口与实现

examples/github 把 interface 放在 api.go，把生成的实现放在 api.gen.go。

运行时的 HTTP 客户端

pkg/clients/resty/example/main.go 把 resty.DefaultClient 传给 genapi.WithHttpClient。

基础配置

examples/github/api/api.go 在 interface 上写了 @BaseURL 和 @Header。

HTTP 方法

examples/github 使用 @GET 和 @POST。website/api/todo.go 还使用 @PUT 和 @DELETE。解析器接受这些名字，以及 RequestLine.alias 返回的别名。

参数

路径里的 {owner} 这类占位符对应同名参数。端到端测试里的 @Query 接受一个 key 和一个 value。写成 {name} 的 value 取自同名参数。

请求体

CreateIssue 接收一个 Issue。生成的方法把 Body 设为这个值。

响应

Contributors 返回 ([]Contributor, error)，生成的方法调用 genapi.HandleResponse。CreateIssue 返回 error，生成的方法调用 genapi.HandleResponse0。单个非 error 的返回值会使用 genapi.MustHandleResponse，binder 里就是这样写的。

请求头

GitHub interface 为每次调用设置 Accept。httpbin 端到端测试还给方法设置了请求头。两处都是 @Header 加名字和值。
